## analysis agent (set list + auto mix round)

- analysis (src/analysis/bpm.js): `BeatInfo.beats` is a `Float64Array` (track seconds, increasing) from the first beat >= 0 to the end of the track, with `beats[0] === firstBeat`; `null` exactly when `bpm` is null. Steady tracks get the exact constant grid (`firstBeat + k * 60 / bpm`), so map- and grid-based code agree to the microsecond. Variable tracks get the tracked map: 16-beat local folds every 4 beats in the map's own coordinate (stage 7 in the file header), drumless intros / outros continued as a straight grid at the local tempo. For a variable track `bpm` is the average tempo over the tracked stretch (beats / time) and `firstBeat` is `beats[0]` (not the fold anchor). The map belongs to the detected tempo: when a deck replaces bpm/firstBeat (user x2, /2, TAP, `setBpm`, or the known demo values in `demoBeats`), it should drop the map (use the grid) instead of mixing the two.
- analysis: `variable` is now decided by the beat map when it covers >= 20 s and followed the beat in >= 75 % of the windows with music: the map's residuals from one straight grid, smoothed over +-8 beats, RMS > 6 ms or 95th percentile > 12 ms (a bending map must also line up the onsets better than the straight grid). The old Fourier-residual / per-beat-regression rule only decides when there is no usable map. Real-song regression (tests/realsongs.test.js): Boss Battle Groove 148.096, steady (3.3 ms RMS), confidence 1; Bubble Star Parade 140.29 (local 140.12 -> 140.51), Arcade Rush 141.52, Kaleidoscopic Loop 141.07 (140.50 -> 141.55), all variable, maps within ~2 ms (median) of an independent beat tracker's maps and of the kick onsets.
- analysis: confidence factor for variable tempo is 0.8 when the map follows the drift (contrast then measured in the map's coordinate), still 0.5 without a usable map; steady tracks unchanged.
- analysis (src/analysis/loudness.js): `gainDb` = -13 dBFS RMS target (90th percentile of 400 ms windows), capped so `peakDb + gainDb <= +2`, clamped -12..+6 (CONTRACT section 3 said -12 target, clamp -12..+9). Extra exports `TARGET_RMS_DB`, `PEAK_CEILING_DB`, `GAIN_MIN_DB`, `GAIN_MAX_DB`.
- analysis (src/analysis/analyze-worker.js): the result message transfers `beats.beats.buffer` (the map is not copied).
- analysis tests: `tests/beatmap.test.js` (synthetic: constant = grid, 0.5 % wobble and 120 -> 124 ramp within 10 ms of truth, drumless intros, humanize stays steady), `tests/realsongs.test.js` (your own WAV files in tests/media/, skipped with a `# SKIP` line when missing; ~25 s alone, ~45 s inside a full parallel `jscheck test tests`). Note for the reference values: the reference tracker's map of Arcade Rush has one extra beat in the fill + breakdown at 62-73 s (the kicks after it sit every 2 beats of a steady ~141.3 grid), so its "~141.9" average is ~0.4 high; the real average is ~141.5.
- analysis (refinement of the bullet above): a straight map proves a steady tempo when it followed the beat in >= 50 % of the windows with music (songs with long breakdowns); a bending map is used as the grid only from 75 %.
