# research-pwa
## Findings
- [high,critical] Spec IDL marks these [SecureContext] (undefined/absent over plain http): BaseAudioContext.audioWorklet, AudioWorklet, AudioWorkletNode, AudioContext.setSinkId/sinkId, HTMLMediaElement.setSinkId, navigator.mediaDevices as a whole (getUserMedia, enumerateDevices, selectAudioOutput), navigator.serviceWorker + self.caches (CacheStorage), navigator.wakeLock, navigator.clipboard, navigator.storage (persist/estimate/OPFS), File System Access pickers/handles. NOT gated by spec: AudioContext itself, decodeAudioData, AudioBufferSourceNode, ScriptProcessorNode, IndexedDB, localStorage, <input type=file>, Fullscreen API, navigator.vibrate, screen.orientation, navigator.mediaSession, navigator.audioSession.
- [high,critical] Opening the dev server from a phone at http://192.168.x.x is NOT a secure context: audioCtx.audioWorklet === undefined and AudioWorkletNode is undefined (engine silently falls to ScriptProcessor), no service worker/Cache API, no wakeLock, navigator.mediaDevices undefined (so no enumerateDevices/setSinkId). Only http://localhost / 127.0.0.1 are exempt. Chrome (desktop and Android) can whitelist an origin via chrome://flags/#unsafely-treat-insecure-origin-as-secure; iOS Safari has no such override, so iPhone testing needs real HTTPS.
- [high,critical] Two simultaneous outputs (master -> BT speaker, cue -> BT headphones) are NOT achievable from a browser on Android or iPhone. Chrome Android: HTMLMediaElement.setSinkId 'not available due to a limitation in Android' (crbug 41276355, untouched since 2022); Chrome's Audio Output Devices intent: 'not supported on Android (including WebView) because the Android platform does not provide the ability to programmatically switch individual audio streams to different audio devices'. AudioContext.setSinkId (Chrome 110) is nominally on all Blink platforms but Android enumerates only the default output. Safari 18.4 speaker selection (enumerate speakers after mic permission + HTMLMediaElement.setSinkId) is macOS only, not iOS (MDN BCD 'mirror' for safari_ios is misleading). Works on desktop: Chrome/Edge 110+ AudioContext.setSinkId (two AudioContexts or MediaStreamDestination -> <audio>.setSinkId), Firefox 116+ and Safari macOS 18.4+ via HTMLMediaElement.setSinkId. Output lists are only exhaustive after getUserMedia({audio:true}) permission.
- [high] Permissions Policy 'speaker-selection' (default allowlist 'self') blocks audio-output enumeration and both setSinkId variants (NotAllowedError) inside iframes unless the embedder adds allow="speaker-selection"; likewise screen-wake-lock, fullscreen, microphone, autoplay need iframe allow attributes. A sandboxed iframe loaded from an https URL is still a secure context.
- [medium] Sandboxed iframe without allow-same-origin (opaque origin): localStorage/IndexedDB throw, reading navigator.serviceWorker throws SecurityError in Chromium, module/worklet fetches become CORS requests with Origin: null. Programmatic input.click() on a hidden file input is reported to be refused in sandboxed preview iframes; a native <label> wrapping the input works.
- [high] Screen Wake Lock: Chrome 84 (desktop+Android), Safari 16.4 in browser tabs, but iOS/iPadOS Home Screen (standalone) web apps only from 18.4 (WebKit bug 254545 broke it 16.4-18.3), Firefox 126. Secure context only; the sentinel is auto-released when the page becomes hidden and must be re-requested on visibilitychange.
- [high] Fullscreen API: Chrome Android 71+ unprefixed (requestFullscreen({navigationUI:'hide'}) needs a user gesture). iPhone Safari: no element fullscreen on any version (MDN BCD note 'Only available on iPad, not on iPhone'; only <video>.webkitEnterFullscreen). iPadOS: unprefixed 16.4 (prefixed 12) with a non-removable overlay button; swipe-down exits. On iPhone the only chrome-less mode is a Home Screen web app (status bar still visible).
- [high] screen.orientation.lock(): Chrome Android 38+ but typically only while fullscreen; Chrome 136 restricts it to phones (tablets/large foldables reject with NotSupportedError); Safari/iOS: not supported at all; Firefox 144. Manifest 'orientation' is honored by installed Chrome PWAs but ignored by iOS.
- [high] Chrome installability (2026): name/short_name, icons incl. 192px and 512px, start_url, display/display_override, prefer_related_applications false, HTTPS or localhost. A service worker with fetch handler is no longer required for menu install since Chrome 108 (Android)/112 (desktop); the automatic beforeinstallprompt still prefers one. beforeinstallprompt: Chrome 61+/Samsung 8+, never on Safari/iOS (or Chrome/Edge on iOS) or Firefox.
- [high] iOS Home Screen: installable from the Share menu in Safari and third-party browsers since iOS 16.4; since iOS 26 every site added to the Home Screen opens as a web app by default ('zero requirements for installability'), user can untoggle 'Open as Web App'. iOS ignores manifest display fullscreen/minimal-ui (falls back to standalone), orientation and background_color; manifest icons are used (15.4+) only when no apple-touch-icon exists and purpose is 'any' (maskable is ignored).
- [high] Storage on iOS (Safari 17+): per-origin quota up to 60% of disk for browser apps and Home Screen web apps (overall 80%); StorageManager.persist() since Safari 15.2, granted by heuristics such as being a Home Screen web app; LRU eviction exempts persistent origins. The ITP 7-day cap deletes IndexedDB, Cache API and SW registrations after 7 days of Safari use without interaction with the site; Home Screen web apps have their own day counter and are not expected to lose data.
- [medium,critical] iOS Web Audio needs navigator.audioSession.type = 'playback' (Audio Session API, Safari 16.4+, not in Chrome): otherwise Web Audio uses the ambient category and is MUTED by the ring/silent switch, and the AudioContext is suspended/'interrupted' when the page is backgrounded or the phone locks. With 'playback', background/lock-screen playback works since iOS 17.5 (WebKit bug 261554 fixed 2024-03-01; regressed in 17.2-17.3).
- [high] Media Session for Web-Audio-only pages (survey by Mozilla engineer, w3c/mediasession#378, 2026-09-24): Chromium activates a session (notification/lock-screen controls) when the AudioContext is audible and mediaSession.playbackState is not 'none', dropping it ~2 s after silence or on suspend(). WebKit activates when audioSession.type is 'playback'/'play-and-record' and the context is running; platform play/pause suspends/resumes the AudioContext directly and page action handlers are ignored. Firefox: not yet.
- [medium] Android Chrome: an audible tab keeps rendering Web Audio with screen off or app switched (audible tabs are exempt from background freezing/intensive throttling), but requestAnimationFrame stops and timers are throttled; OEM battery optimisation can still kill the tab during long screen-off periods.
- [low] iOS 26 Home Screen web apps have reported audio regressions (26.0.1: AudioContext.resume() in a click fails with 'InvalidStateError: Failed to start the audio device'; playback stops when locked); the same pages work in a Safari tab. Earlier lock-screen bug for standalone apps (WebKit 198277) was fixed in iOS 15.4.
- [medium,critical] File picking on iOS: a bare accept="audio/*" greys out .m4a (and reportedly .mp3) in the Files picker because Safari/Chrome fail to map UTIs back to the wildcard; listing explicit MIME types and extensions (with audio/* last) fixes it (Gradio PR #4071 confirmed on iPhone). Apple Music library/streaming tracks are not reachable from a web page; users must have DRM-free files in Files/iCloud Drive/Downloads.
- [high] File System Access API: Chrome desktop 86; Chrome Android 132 (Jan 2025) has showOpenFilePicker/showDirectoryPicker/getAsFileSystemHandle, but MIME filters are ignored, persistent permissions are limited and large folders can hang; Safari and Firefox: none. OPFS (navigator.storage.getDirectory) exists in Safari 15.2+, Chrome Android 109+.
- [high] GitHub Pages (verified with curl on 2026-10-06): every file is served with Cache-Control: max-age=600 and Access-Control-Allow-Origin: *; .js is served as application/javascript and .webmanifest as application/manifest+json; custom headers are impossible, so COOP/COEP cannot be set (no crossOriginIsolated, no SharedArrayBuffer). Limits: 1 GB site, 100 GB/month soft bandwidth, 10 builds/hour soft, HTTP 429 when rate-limited.
- [high] No-account / drag-and-drop hosting: Netlify Drop anonymous deploys are removed after 1 hour unless claimed; Cloudflare Drop (cloudflare.com/drop, launched 2026-07-08) needs no account, gives a 1-hour live preview, claim to keep, max 1,000 files of 25 MiB each; Cloudflare Pages Direct Upload (dashboard drag-and-drop zip/folder, needs account) gives <project>.pages.dev, 1,000 files/25 MiB, and cannot be switched to Git integration later.
- [high] Cloudflare quick tunnel ('cloudflared tunnel --url http://localhost:PORT') gives a random https://*.trycloudflare.com URL: 200 in-flight requests (then 429), no SSE, no uptime guarantee, new hostname each run, publicly reachable. A local copy of cloudflared 2026.10.0 (tools\cloudflared\cloudflared.exe) and an HttpListener static server (tools/serve.ps1) were used for testing. Tested locally: that HttpListener (prefix http://localhost:PORT/) returns HTTP 400 for any other Host header (incl. 127.0.0.1 and *.trycloudflare.com), so the tunnel must pass --http-host-header localhost:PORT.
- [high] Android over USB: Chrome DevTools port forwarding (chrome://inspect > Port forwarding) maps the phone's localhost:PORT to the PC, so the phone loads http://localhost:PORT, which IS a secure context (AudioWorklet, SW, wake lock all work) without HTTPS. No iOS equivalent.
- [high] Service worker updates: default updateViaCache 'imports' (Chrome 68+, Firefox, Safari) means sw.js itself bypasses the HTTP cache on update checks, but files fetched inside the SW (cache.addAll, fetch) still honour HTTP caching (GitHub Pages max-age=600), so a new SW can precache stale copies unless requests use cache:'reload'/'no-cache'.
- [high,critical] User activation: per the HTML spec, pointerdown only counts as activation for pointerType 'mouse'; on touch only pointerup/touchend (and click) are activation-triggering. AudioContext.resume(), requestFullscreen, file pickers and vibrate called from a touch pointerdown (e.g. first touch on a platter) can fail.
- [medium] Viewport: svh/lvh/dvh units in Safari/iOS 15.4, Chrome 108, Firefox 101; Safari 26 (iOS 26) ignores <meta name=theme-color> and the manifest theme_color for toolbar tint and instead samples fixed/sticky elements near the top and bottom edges or the body background; set explicit html/body background-color; viewport-fit=cover + env(safe-area-inset-*) for notches/home indicator.
- [medium] navigator.vibrate: Chrome Android 32+ only (needs user activation since Chrome 60, blocked in cross-origin iframes), removed from Firefox 129, never in Safari/iOS. The iOS <input type=checkbox switch> haptic hack (17.4-26.4) was patched in iOS 26.5.
- [high] AudioContext.outputLatency is available in Chrome 102, Safari 18.4, Firefox 70; useful for compensating Bluetooth latency (often 150-300 ms) in beat-phase display and sync.
- [medium] Safari 27.0 (released 2026-09-17) adds Service Worker static routing (InstallEvent.addRoutes, Chrome 123+) and fixes background playlist advance; it adds nothing for iPhone element fullscreen, orientation lock, setSinkId on iOS or the Vibration API.
## Recommendations
- HOSTING: use GitHub Pages as the permanent home (free, HTTPS, stable URL). Reuse the usual publish-script pattern (build site/ folder, add .nojekyll, push to gh-pages with Git Credential Manager; -Zip makes a zip for Netlify Drop / Cloudflare Drop). Since it is a project site served under /<repo>/, use only relative URLs everywhere: manifest start_url './' and scope './', navigator.serviceWorker.register('./sw.js'), new URL('./engine/deck-processor.js', import.meta.url) for the worklet. Never use leading-slash paths.
- Do not use SharedArrayBuffer, so COOP/COEP headers are never needed and GitHub Pages works. Move decoded PCM into the AudioWorklet with postMessage(…, [buffer.buffer]) as transferables, once per channel per track load.
- PHONE TESTING WITHOUT NODE: (a) Android over USB: run tools/serve.ps1-style HttpListener on localhost:8090, chrome://inspect > Port forwarding 8090 -> localhost:8090, then open http://localhost:8090 on the phone (secure context). (b) Any phone incl. iPhone: put cloudflared.exe in tools\cloudflared\ and run: cloudflared tunnel --no-autoupdate --url http://localhost:8090 --http-host-header localhost:8090, then open the printed https://*.trycloudflare.com URL. Make a tools/phone-test.ps1 that starts both and copies the URL (same structure as a serve-plus-tunnel script). Never test via http://192.168.x.x: AudioWorklet will be undefined.
- Startup capability probe, logged to an on-screen debug panel: isSecureContext, typeof AudioWorkletNode, 'audioWorklet' in BaseAudioContext.prototype, 'setSinkId' in AudioContext.prototype, 'setSinkId' in HTMLMediaElement.prototype, !!navigator.mediaDevices, 'wakeLock' in navigator, 'audioSession' in navigator, document.fullscreenEnabled, matchMedia('(display-mode: standalone)').matches || navigator.standalone, crossOriginIsolated, window.top !== window (embedded). If !isSecureContext, show a banner: 'Open via https:// for best audio (scratch engine fallback active)'.
- DUAL OUTPUT: treat it as a desktop feature. Show the 'Cue to a second device' picker only when isSecureContext && (AudioContext.prototype.setSinkId || HTMLMediaElement.prototype.setSinkId) AND, after getUserMedia({audio:true}) is granted and the stream is stopped, enumerateDevices() returns more than one audiooutput. Desktop Chrome/Edge: master context + cue context, each with setSinkId(deviceId) (or one context with two MediaStreamAudioDestinationNodes -> two <audio> elements with setSinkId on Safari macOS 18.4+/Firefox 116+). On phones always offer SPLIT CUE: master summed to mono on the left channel and cue summed to mono on the right channel of one headphone output, plus a 'cue mix' knob. Say plainly in the UI that phones cannot send to two Bluetooth devices at once.
- iOS AUDIO SETUP: before creating/resuming the AudioContext run: if ('audioSession' in navigator) navigator.audioSession.type = 'playback'; (stops the silent switch muting Web Audio and keeps audio alive in background/lock on iOS 17.5+). Create/resume the AudioContext inside a click or pointerup handler of a large 'Tap to start' splash, never on pointerdown. Listen to ctx.onstatechange: when state is 'interrupted' or 'suspended' (phone call, Siri, other app), show a 'Tap to resume audio' overlay and call ctx.resume() on the next click; also try resume on visibilitychange to visible.
- MEDIA SESSION: when any deck plays set navigator.mediaSession.metadata = new MediaMetadata({title: deckA/B track names, artist: 'TwinSpin', artwork: [{src:'icons/icon-512.png', sizes:'512x512', type:'image/png'}]}) and navigator.mediaSession.playbackState = 'playing' ('paused' when both decks stop). Register play/pause handlers that start/stop both decks (Chromium may call them); on WebKit the OS suspends/resumes the AudioContext directly, so keep UI state synced from ctx.onstatechange.
- WAKE LOCK: request navigator.wakeLock.request('screen') in the first 'Tap to start' click and whenever a deck starts playing; re-request on document visibilitychange to visible; release when both decks have been stopped for a few minutes. Wrap in try/catch (fails in iframes without allow="screen-wake-lock", in iOS standalone below 18.4 and over http).
- FULLSCREEN/ORIENTATION: offer a Fullscreen button only when document.fullscreenEnabled (Android Chrome, desktop, iPad): document.documentElement.requestFullscreen({navigationUI:'hide'}) from a click. On iPhone hide the button and show a one-time hint 'Share > Add to Home Screen for full-screen mode' when not standalone. Never call screen.orientation.lock; design a responsive layout that works in portrait (decks stacked, mixer between) and landscape (decks side by side, mixer centre).
- LAYOUT CSS: <meta name=viewport content="width=device-width, initial-scale=1, viewport-fit=cover">; app root position:fixed; inset:0; height:100dvh (fallback 100vh) with overflow:hidden so the page never scrolls and the toolbar never collapses; padding using env(safe-area-inset-top/right/bottom/left); html,body{background:#0b0b12} explicitly (Safari 26 samples this for toolbar tint); overscroll-behavior:none on html/body (prevents pull-to-refresh); touch-action:none on platters, faders and knobs; user-select:none; -webkit-user-select:none; -webkit-touch-callout:none; -webkit-tap-highlight-color:transparent.
- MANIFEST (manifest.webmanifest): {"id":"./","name":"TwinSpin DJ","short_name":"TwinSpin","start_url":"./","scope":"./","display":"fullscreen","display_override":["fullscreen","standalone"],"orientation":"any","background_color":"#0b0b12","theme_color":"#0b0b12","icons":[192 png any, 512 png any, 512 png maskable (logo inside the central 80% safe zone)]}. Also add <link rel=apple-touch-icon href=icons/apple-touch-icon-180.png> (opaque PNG, no transparency), <meta name=apple-mobile-web-app-status-bar-style content=black-translucent>, <meta name=theme-color content=#0b0b12> (Chrome Android still uses it). Generate the PNGs with a small C#/.NET script or a small .NET canvas-rendering tool (no Node).
- INSTALL UX: on Android capture beforeinstallprompt (preventDefault, keep the event) and show an 'Install app' button that calls prompt() once. On iOS (no beforeinstallprompt) show 'Share > Add to Home Screen' instructions only when !(navigator.standalone || matchMedia('(display-mode: standalone)').matches).
- SERVICE WORKER (sw.js, no build step): const VERSION = 'twinspin-__BUILD__' (have the publish script replace __BUILD__ with a timestamp so every deploy changes sw.js bytes); SHELL = list of index.html, css, every JS module including the worklet file, the manifest and icons. install: caches.open(VERSION).then(c => c.addAll(SHELL.map(u => new Request(u, {cache:'reload'})))). activate: delete every cache whose name is not VERSION, then clients.claim(). fetch: handle only same-origin GET requests; for navigations and .html/.js/.css use network-first with fetch(req, {cache:'no-cache'}), a 3 s timeout, cache.put on success and the cached copy as fallback; for icons/images use cache-first. Ignore blob:, data: and non-GET requests (user tracks never touch the SW). Do not skipWaiting automatically: on 'updatefound' -> 'installed' with an existing controller show 'Update ready, reload when you're not playing' and postMessage('skipWaiting') on tap.
- DEV STALE-CACHE GUARD: do not register the SW when location.hostname is localhost/127.0.0.1 or the URL has ?nosw, and unregister any existing registration in that case; keep serve.ps1's Cache-Control: no-store; on desktop use DevTools Application > 'Update on reload'. Show the build stamp (VERSION) in a settings/about panel so you can see which version is running on the phone.
- FILE INPUT: <label class="load-btn">Load track<input type="file" hidden multiple accept=".mp3,.m4a,.aac,.mp4,.wav,.wave,.aif,.aiff,.flac,.ogg,.oga,.opus,.webm,audio/mpeg,audio/mp4,audio/x-m4a,audio/aac,audio/wav,audio/x-wav,audio/aiff,audio/flac,audio/ogg,audio/webm,audio/*"></label>. The label wrapper opens the picker natively, so it also works in sandboxed previews. Decode with ctx.decodeAudioData(await file.arrayBuffer()) inside try/catch and show 'This format can't be played in this browser' on failure. Add a short 'Where are my songs?' hint: iPhone uses MP3/M4A/WAV saved in the Files app, Apple Music/Spotify tracks can't be loaded.
- DESKTOP DRAG & DROP: each deck is a drop target (dragover preventDefault + highlight; drop -> e.dataTransfer.files[0]); dropping on the mixer goes to the first empty deck. Optional on Chrome desktop only: when the 'showOpenFilePicker' in window check passes, store FileSystemFileHandles in IndexedDB to reopen files later (call handle.requestPermission({mode:'read'}) inside a click). Skip the File System Access API on Android: MIME filters are ignored and persistent permissions are limited.
- TRACK LIBRARY: store the original File/Blob (compressed, not the decoded PCM) in IndexedDB with metadata {name, size, lastModified, durationSec, bpm, firstBeatSec, waveform overview peaks (e.g. 1,000 Uint8 values)} so reloading a known track skips BPM analysis. Call navigator.storage.persist() after the first save (best granted for installed apps) and show navigator.storage.estimate() usage plus a 'Remove' button per track and a 'Clear library' button. Cap the library (e.g. 30 tracks / 1 GB) and wrap every IndexedDB call in try/catch so the app still works when storage is blocked.
- BACKGROUND RESILIENCE: run all timing-critical logic (sync phase correction, loops, crossfader automation) inside the AudioWorklet/audio graph, not in requestAnimationFrame or setInterval, because rAF stops and timers are throttled when the screen is off or the app is backgrounded. Treat background playback as best effort: the expected DJ use is screen-on with Wake Lock.
- WORKLET LOADING: await ctx.audioWorklet.addModule(new URL('./deck-processor.js', import.meta.url)); if that throws (CSP or sandbox in an embedded preview), retry with a Blob URL built from the processor source string, then fall back to the ScriptProcessor engine. Keep the processor in its own file so the SW precaches it.
## Gotchas
- A phone opening http://<PC-LAN-IP>:port silently loses AudioWorklet, the service worker, Wake Lock and mediaDevices; the app appears to work but uses the fallback engine. Always test via HTTPS (tunnel or deployed site) or USB-forwarded localhost.
- The iPhone ring/silent switch mutes Web Audio unless navigator.audioSession.type = 'playback' is set before audio starts. This is the top 'no sound on iPhone' bug report.
- On touch screens, pointerdown is not a user activation. Unlocking audio on the first platter touch (pointerdown) fails; do it on click/pointerup.
- A tools/serve.ps1-style server (HttpListener on http://localhost:PORT/) answers 400 to tunnel requests unless cloudflared is given --http-host-header localhost:PORT (verified locally). Quick-tunnel URLs are public and change on every run; never leave one running with private files in the served folder.
- GitHub Pages max-age=600 plus the Fastly CDN means a fresh deploy can take up to about 10 minutes to reach phones, and a SW precache can capture the old files unless requests use cache:'reload'.
- Leading-slash URLs ('/sw.js', '/icons/…') break on GitHub Pages project sites (/repo/ path) and in previews; use relative URLs everywhere.
- Safari tab storage is wiped after 7 days of Safari use without visiting the site; Home Screen apps are effectively exempt. Data saved in a Safari tab may not appear in the installed Home Screen app (its storage container is believed to be separate; verify on a device), so tell users to install first and then build their library.
- iOS Home Screen apps below iOS 18.4 cannot hold a Wake Lock (screen sleeps during a set); Safari tabs could from 16.4.
- iPhone has no element Fullscreen API and no orientation lock. Feature-detect and hide those buttons instead of letting them throw.
- Safari 26 ignores theme-color for toolbar tint and samples fixed/sticky elements near the screen edges or the body background. A translucent fixed footer (e.g. the crossfader bar) changes the toolbar colour; put backgrounds on an absolute child or set an explicit body background.
- Decoded PCM is large: a 6-minute stereo track at 48 kHz in Float32 is about 138 MB, so two decks are about 276 MB. iPhones can kill the tab under memory pressure; free the old buffers when a deck loads a new track and consider limiting track length or keeping Float32 only in the worklet.
- Bluetooth adds roughly 150-300 ms of output latency, and it differs between a speaker and headphones. Even on desktop dual-output, cue and master will not be phase-aligned; use outputLatency/baseLatency for the visuals and sync display.
- Chrome on Android cannot route different streams to different outputs (OS limitation). Samsung 'Dual Audio' or Auracast sharing mirror the same stream to two devices; they do not give separate cue and master.
- Embedded/sandboxed preview: storage and serviceWorker getters can throw (wrap them in try/catch); setSinkId, Wake Lock, fullscreen and the microphone permission need the iframe allow= attributes; a programmatic input.click() may be ignored.
- Media Session on Chromium disappears about 2 s after silence or after ctx.suspend(), so lock-screen controls vanish while paused if the context is suspended. Keep the context running (silent) while decks are paused if controls should persist.
- iOS 26.x Home Screen apps had reported AudioContext start failures ('Failed to start the audio device'). Provide a 'Tap to resume audio' recovery path, and mention that the Safari tab works as a fallback.
- navigator.vibrate is absent on iOS and the switch-checkbox haptic hack stopped working in iOS 26.5. Use visual and audio feedback, with vibrate only as an optional Android extra.
- Chrome Android 132+ File System Access ignores MIME filters and has limited persistent permissions; don't build the library on it.
