# verify-gdrive
- **partly-true**: 1. Drive API media downloads are CORS-enabled for both TwinSpin origins. Preflight returns 200, Access-Control-Allow-Origin echoed, Allow-Methods includes GET, Allow-Headers 'authorization,range,x-goog-drive-resource-keys', Max-Age 3600. GET responses expose Content-Length but not Content-Range.
  - CORRECTION: The preflight part is confirmed by a live re-test. The exposed-headers part was only seen on error responses (403 with no auth, 401 with a bogus token), not on a real 200/206 media download, so it is unverified for successful downloads. The two error paths also expose different header lists. Content-Range was absent from both lists, so code should not depend on reading it.
- **partly-true**: 2. drive.file is Non-sensitive. drive.readonly, drive and drive.metadata.readonly are Restricted, which means verification plus an annual security assessment. Google recommends drive.file with the Google Picker for per-file access.
  - CORRECTION: The scope classifications and the Picker recommendation are correct. The annual third-party security assessment (CASA) applies only when restricted-scope data is accessed, stored or transmitted from or through a server. A purely client-side app would still need restricted-scope verification, but not necessarily the assessment. This is minor: the conclusion to avoid restricted scopes stands.
- **confirmed**: 3. The unverified-app screen and the 100-user cap are triggered only by sensitive or restricted scopes. A drive.file-only app can be set to In production (External) without verification. In Testing: 100 listed test users, an unverified warning, and authorizations expire 7 days after consent.
  - CORRECTION: Correct, with two additions. (a) The unverified-app screen also appears when the scopes requested in code differ from the scopes configured on the consent screen, so drive.file must be added on the Data Access page. (b) In Testing status the warning and 7-day expiry apply to drive.file too; only basic identity scopes are exempt.
- **partly-true**: 4. Without brand verification the consent screen shows only the domain, not 'TwinSpin'. Brand verification needs a homepage and privacy policy on a Search-Console-verified authorized domain. On github.io this is reportedly unreliable (forum case stuck 36+ hours), so treat it as cosmetic or move to a custom domain.
  - CORRECTION: The domain-only display and the requirements are confirmed. 'Unreliable on github.io' is unverifiable: no primary source was found. github.io is on the Public Suffix List, so ranama.github.io is itself a top private domain and can be verified in Search Console (for example with a meta tag on GitHub Pages). Two points were missed. (a) Google says homepage and privacy-policy links are 'required for all external production apps', so publish a privacy page anyway. (b) Uploading a logo triggers verification, so do not upload one.
- **confirmed**: 5. The API key's website restrictions must include https://docs.google.com/* plus the app origins, or the Picker fails with 'API developer key is invalid'. Restrict the key's APIs to Google Picker API (and Drive API).
  - CORRECTION: Correct. Google adds the Drive API to the key restriction only 'if your app calls it directly' with the key. In approach A, Drive calls use the Bearer token. See the extra finding about TwinSpin's no-referrer meta tag, which likely defeats website-restricted keys.
- **partly-true**: 6. setAppId must be the numeric Cloud project NUMBER from the same project as the OAuth client. It is required for drive.file; without it, picked files are not usable by the app.
  - CORRECTION: Documented: setAppId takes the Cloud project number and 'is required for the drive.file scope'. Not documented: the 'same project as the OAuth client' rule and the stated consequence that picked files are not usable. Both are reasonable inferences, but Google does not state them.
- **confirmed**: 7. GIS token model (initTokenClient) is current and not deprecated (page updated 2026-05-26). No backend, no refresh token, popup-only, needs a user gesture. prompt defaults to 'select_account'; '' prompts only the first time. error_callback types are popup_failed_to_open, popup_closed and unknown. expires_in is in seconds, typically 3599-3600.
  - CORRECTION: Correct. Minor date mix-up: 2026-05-26 is the last-updated date of the token-model guide; the js-reference page was updated 2025-08-20. Google's docs say 'only the dialog UX is supported' and do not use the word popup. The 3599-3600 figure is typical observed behavior; Google documents only 'lifetime in seconds'. In the reference, the only deprecations are enable_granular_consent and enable_serial_consent.
- **partly-true**: 8. Google makes no mobile-browser support statement for the web Picker. The web Picker is the only option for a web page; the trigger_onepick Picker is for desktop/native apps and returns a code needing a backend exchange. setSize minimum is 566x350. The Picker cannot run in embedded webviews or in-app browsers. Expect it to work in iPhone Safari and Android Chrome, but verify.
  - CORRECTION: Confirmed: there is no mobile statement, setSize min 566x350 / max 1051x650 is documented, and trigger_onepick is explicitly not for client pages. Three corrections. (a) The onepick redirect returns 'the access token or access code based on the response_type', so it is not strictly a code needing a backend. Google still directs web pages to the web Picker. (b) The 'can no longer be displayed within an embedded webview' statement is in the desktop/mobile column; for web, embedded webviews are blocked by Google OAuth (disallowed_useragent) rather than by a Picker statement. (c) Missed: Google now also offers a Picker web component, @googleworkspace/drive-picker-element (npm latest 0.7.3), which the web guide links. Also unverified: Safari's cross-site tracking prevention may affect the docs.google.com Picker iframe on iPhone.
- **partly-true**: 9. TwinSpin's manifest sets display:standalone. OAuth popup flows are known to fail in iOS home-screen apps while redirect flows work, so add a redirect token fallback (OAuth 2.0 implicit endpoint, response_type=token, redirect URI https://ranama.github.io/twinspin/).
  - CORRECTION: display:standalone is confirmed in both the local and live manifests. The popup failure is supported only by anecdotal or older reports, not by Apple or Google documentation. Two caveats against the fallback. (a) Google's implicit-flow page (updated 2026-10-15) says calling the implicit endpoints directly is 'strongly discouraged' and 'provided only for legacy support and troubleshooting'. It still works and is the only no-backend redirect option, since the GIS code model needs a backend exchange. (b) A full-page redirect unloads the running audio engine and decks, so it must never fire mid-mix. Also, iOS home-screen apps do not share storage with Safari, so 'import in a Safari tab instead' does not fill the installed app's library. The OS file picker (Files app with Google Drive) is the safest standalone fallback.
- **unverifiable**: 10. Selecting a folder in the Picker under drive.file does not grant access to the files inside it. Users must pick the files themselves. Whole-folder import needs drive.readonly (restricted) or a public folder link plus an API key.
  - CORRECTION: Google's docs neither confirm nor deny whether a picked folder grants drive.file access to its children. setSelectFolderEnabled and allow_folder_selection exist, and drive.file is described as covering files the user 'opens with the app or shares with it through a picker'. The claim matches common developer understanding but should be tested: pick a folder, then call files.list with q='<folderId>' in parents and files.get on a child. Public-folder listing with an API key is plausible but was not tested; older link-shared files may need resource keys.
- **confirmed**: 11. Picker filtering uses View.setMimeTypes or PickerBuilder.setSelectableMimeTypes with comma-separated MIME types. Wildcards are undocumented, and there is no audio ViewId. DocsView methods as listed. LIST mode is recommended with drive.file.
  - CORRECTION: Correct. The ViewId list also has deprecated members (IMAGE_SEARCH, MAPS, PHOTOS, RECENTLY_PICKED, YOUTUBE, etc.). Because Drive's stored audio MIME types vary (audio/mpeg, audio/mp4, audio/x-m4a, audio/wav, audio/x-wav, audio/flac, audio/x-flac, audio/ogg, audio/aac...), the exact-match list must be broad. Alternatively, filter in the callback (this is an inference).
- **confirmed**: 12. files.get?alt=media for blob files; Range supported; Workspace docs need files.export (10 MB cap); check capabilities.canDownload; abusive files need acknowledgeAbuse=true. Shortcuts have mimeType application/vnd.google-apps.shortcut with shortcutDetails.targetId; Picker or drive.file access to the target is undocumented.
  - CORRECTION: All points are confirmed. Partial (Range) downloads are not available for Workspace exports.
- **confirmed**: 13. Picker DocumentObject has id, name, mimeType, sizeBytes (not for in-session uploads), lastEditedUtc, parentId, resourceKey. When resourceKey is non-empty, send X-Goog-Drive-Resource-Keys: {id}/{resourceKey}; the preflight allows this header.
  - CORRECTION: Correct. Multiple pairs are comma-separated. DocumentObject also offers duration, isShared, url and downloadUrl.
- **confirmed**: 14. Authorized JavaScript origins are bare origins (no path, query or fragment); HTTPS is required except for localhost. Register https://ranama.github.io and http://localhost:8100. The client secret is not used. Since 2025, OAuth clients unused for 6 months are auto-deleted (restorable for 30 days), and client secrets are masked after creation.
  - CORRECTION: Correct. Google's GIS setup page also says to add both http://localhost and http://localhost:<port> for local development, so register http://localhost as well. Redirect URIs must match exactly, including scheme, case and trailing slash. Deletion is driven by lack of token activity, so if nobody uses the Drive button for 6 months the client is deleted. Restoring within 30 days is possible.
## Extra findings
- HIGH: TwinSpin ships a no-referrer policy, <meta name="referrer" content="no-referrer">, in D:\Claude\TwinSpin\index.html line 16, and the live https://ranama.github.io/twinspin/ has it too. Website-restricted API keys are matched against the browser's referrer. docs.cloud.google.com/docs/authentication/api-keys notes that browser referrer behaviour limits which restrictions work. Google's GIS setup page (developers.google.com/identity/gsi/web/guides/get-google-api-clientid, updated 2026-04-06) recommends Referrer-Policy strict-origin-when-cross-origin, and no-referrer-when-downgrade for http localhost testing. Expected impact: the Picker developer key, and approach B fetch('...?key=') calls, likely fail with API_KEY_HTTP_REFERRER_BLOCKED or 'API developer key is invalid', and GIS origin checks may break. This is inferred, not live-tested. Fix: change the meta to strict-origin-when-cross-origin, or pass referrerPolicy: 'strict-origin-when-cross-origin' on the Drive/Picker requests.
- HIGH: Real-phone testing currently runs through tools\phone-link.ps1, which uses a random https://<words>.trycloudflare.com quick-tunnel host that changes on every run. It cannot be pre-registered as an Authorized JavaScript origin, nor allowed in the API key's website restrictions. Drive/Picker phone tests must use the published https://ranama.github.io/twinspin/ or a fixed named tunnel host added to both lists.
- Google now strongly discourages direct use of the implicit (response_type=token) endpoints. Per the page updated 2026-10-15, they are for 'legacy support and troubleshooting' only. The planned approach C fallback works but goes against current guidance. A full-page redirect also kills the live Web Audio session, so allow it only when the decks are stopped and the app state is saved.
- iOS home-screen web apps do not share storage (IndexedDB) with Safari (Firebase maintainers, github.com/firebase/firebase-js-sdk/issues/77). Telling standalone users to 'import in Safari instead' will not fill the installed app's library. The OS file picker route (Files app with the Google Drive provider) is the zero-OAuth path that works inside standalone mode.
- Google's web Picker guide links an official web component, @googleworkspace/drive-picker-element (npm latest 0.7.3, github.com/googleworkspace/drive-picker-element). It wraps GIS and the Picker and is an alternative to hand-written gapi.load('picker') code. Check its bundle and CDN availability before using it, since TwinSpin has no build step.
- Unverified risk: the web Picker renders in a cross-site docs.google.com iframe. Safari's 'Prevent cross-site tracking' and ITP have broken other embedded Google UIs (for example Drive video embeds). setOAuthToken may avoid the dependence on cookies, but no Picker-specific evidence either way was found. Include this in the iPhone Safari test.
- Consent screen hygiene. Add drive.file to the Data Access scopes list, because a mismatch between code and console scopes triggers the unverified-app screen (support.google.com/cloud/answer/7454865). Provide homepage and privacy-policy links: Google says these are 'required for all external production apps' (support.google.com/cloud/answer/15549049). Do not upload a logo, since that triggers brand verification.
- Enable both the Google Picker API and the Google Drive API in the same Cloud project as the OAuth client. Bearer-token Drive calls fail if the Drive API is not enabled for the token's project.
- Only error responses (403/401) were live-tested. Before relying on progress bars or ranged reads, confirm that a successful 200/206 alt=media download exposes Content-Length to JS. Read Content-Range only if it is exposed; it was not in the observed lists.
