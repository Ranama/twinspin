# research-alternatives
## Verdict
TwinSpin's engine needs the raw, unencrypted audio bytes so that fetch() plus decodeAudioData can turn them into PCM. Only a few sources give that, legally, to a static GitHub Pages site. (1) The user's own files in Dropbox, Google Drive or OneDrive: all three have client-side pickers or OAuth flows that need no backend, and their download endpoints send CORS headers (preflights tested 2026-10-13). (2) Audius: a free open API with no key needed for reads. Its stream endpoint redirects to full-length 320 kbps MP3 with Access-Control-Allow-Origin: * on every hop, and track JSON already includes bpm and musical_key (tested 2026-10-13). (3) Jamendo: Creative Commons catalogue, free client_id for non-commercial use, CORS on both the API and the MP3 hosts (tested). (4) Internet Archive: no key, CORS on search, metadata and download, with Range support (tested); rights vary per item. All four allow full DJ use (BPM analysis, scratch, EQ, mixing), subject to licence and attribution notes. Everything else fails for DJ use. YouTube is IFrame-only, and its Developer Policies (updated 2026-09-14) forbid separating, isolating or modifying the audio, caching, and background play, so it can only be a play-only video player. Apple Music (MusicKit JS), Tidal and Beatport stream DRM-protected audio. Web Audio cannot read it, and DJ access is reserved for signed partners: DJ with Apple Music launched 2025-03-25 for rekordbox, Serato, Engine and djay; Tidal's DJ Extension is partner-only; Beatport's v4 API is partner-gated, and Beatsource merged into Beatport in March 2026. SoundCloud registration reopened in May 2026, but only for Artist Pro subscribers. Every token needs a client secret, so a server is required. Streams have been AAC HLS only since progressive MP3 was removed (announced for 2025-12-31). Its API terms forbid modifying content without the uploader's consent and mixing it with content from other services, which rules out DJ mixing. Deezer stopped new app creation (still reported closed in September 2026). Its public API (JSONP only, no CORS) gives only 30-second preview MP3s, which do have CORS. Bandcamp has no consumer API, but purchases download DRM-free (MP3 320, FLAC, WAV and others) and already work through TwinSpin's local file loader.
## Recommendation
Ranked additions for TwinSpin:
1. Cloud file pickers (the user's own music, full DJ engine, no ToS risk). Start with the Dropbox Chooser: about half a day, an app key and domain registration, no approval needed. Then Google Drive (Picker plus the GIS token client, drive.file only) and OneDrive (MSAL PKCE plus @microsoft.graph.downloadUrl). These pair naturally with Bandcamp or other DRM-free purchases.
2. Audius: the best streaming catalogue for DJ use. No key needed, CORS-open 320 kbps MP3, BPM and key in the metadata, optional PKCE login with no backend. Show artist credit and a link back, skip gated tracks, and pass app_name or a free API key.
3. Jamendo: a CC catalogue with a free client_id. Show the per-track licence and attribution with a Jamendo link, keep TwinSpin non-commercial (no ads), and offer a 'mix-safe' filter that excludes ND tracks for recorded mixes.
4. Internet Archive: no key, CORS-open. Offer a curated browser of Live Music Archive, netlabel and CC or public-domain collections, and show each item's rights statement.
5. Optional and separate: a play-only YouTube IFrame mode on the music-player page only, kept visible with no Web Audio and no background play. Label it clearly as not DJ-capable.
Do not build: SoundCloud (Artist Pro plus a server for the secret; terms forbid modifying or mixing), Apple Music, TIDAL or Beatport (DRM, partner-only DJ rights), or Deezer beyond 30-second previews (app creation closed). Implementation note: every recommended source ends in a plain fetch(url) returning an ArrayBuffer, then decodeAudioData, so a single 'remote source' module with per-provider search and URL resolution can feed the existing deck loader. Fetch signed or expiring URLs immediately before loading the deck.
## Options
### Dropbox Chooser (user's own files)
- **whatWorks**: Full DJ engine: pick one or more audio files from the user's Dropbox, fetch the direct link, run decodeAudioData, then BPM/beat map, scratch, EQ/FX, two-deck mixing, queue, shuffle. The extensions filter can be set to 'audio' and multiselect is supported. Any format the browser can decode works (MP3, AAC/M4A, WAV, FLAC, OGG).
- **requirements**: Free Dropbox developer app (app key). Register the Chooser domains (ranama.github.io, localhost). The docs say the Chooser 'doesn't require production approval'. The user needs a Dropbox account. No backend.
- **termsAndLegal**: These are the user's own files, so Dropbox terms are not a barrier. Rights to the music are the user's responsibility. Direct links are meant for downloading, and the docs say not to use them to display content directly.
- **technical**: dropins.js with data-app-key, Dropbox.choose({linkType:'direct', extensions:['audio'], multiselect:true}). Direct links 'support CORS' and expire after 4 hours, so fetch them right away. Tested 2026-10-13: dl.dropboxusercontent.com returns Access-Control-Allow-Origin: *; the api.dropboxapi.com and content.dropboxapi.com preflights allow the ranama.github.io origin. For a persistent library, the full API with OAuth PKCE also works from a static site.
- **effort**: Low: about half a day (script tag, button, fetch, existing decode path).
- sources: https://docs.dropboxapi.com/dropbox-api/docs/pre-built-components/chooser https://www.dropbox.com/developers/dropins/chooser https://dropboxforum.com/discussions/101000014/cors-problem-when-playing-dropbox-shared-link-mp3-file/285942 curl CORS test 2026-10-13: dl.dropboxusercontent.com, api.dropboxapi.com/2/files/get_temporary_link, content.dropboxapi.com/2/files/download
### Google Drive Picker + Drive API (user's own files)
- **whatWorks**: Full DJ engine on audio files the user picks from Google Drive (fetch alt=media, then decodeAudioData). Same features as local files.
- **requirements**: Google Cloud project with an API key and an OAuth web client ID; JS origins set to ranama.github.io and localhost; OAuth consent screen. Use only the drive.file scope, which is non-sensitive and gets a 'more streamlined verification'. Unverified apps in Testing mode are limited to listed test users until published. No backend: the Google Identity Services token model (initTokenClient/requestAccessToken) gives short-lived access tokens in the browser with no refresh token, so the user re-consents or re-requests when the token expires.
- **termsAndLegal**: User's own files. Requesting the full drive scope would trigger a restricted-scope security assessment, so avoid it. Check capabilities.canDownload before fetching.
- **technical**: Load the Picker and GIS scripts; after picking, GET https://www.googleapis.com/drive/v3/files/{id}?alt=media with an Authorization: Bearer header. Tested 2026-10-13: the googleapis.com preflight returns Access-Control-Allow-Origin: https://ranama.github.io and allows the authorization header.
- **effort**: Medium: 1 to 2 days (Cloud console setup, consent screen, Picker UI, token handling).
- sources: https://developers.google.com/drive/picker/guides/overview https://developers.google.com/workspace/drive/api/guides/api-specific-auth https://developers.google.com/drive/api/v3/manage-downloads https://developers.google.com/identity/oauth2/web/guides/use-token-model https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification curl CORS preflight test 2026-10-13: https://www.googleapis.com/drive/v3/files/{id}?alt=media
### OneDrive File Picker v8 / Microsoft Graph (user's own files)
- **whatWorks**: Full DJ engine on picked OneDrive files, for personal and work accounts.
- **requirements**: Free Microsoft Entra app registration (SPA platform, redirect URIs for GitHub Pages and localhost). MSAL.js with auth code + PKCE needs no backend. Delegated Files.Read scope.
- **termsAndLegal**: User's own files.
- **technical**: Do not call /content from JS: it returns a 302, which 'is explicitly prohibited when a CORS preflight is required'. Instead select @microsoft.graph.downloadUrl, which is preauthenticated, needs no preflight, and expires within minutes, then fetch it. Graph preflight tested 2026-10-13: Access-Control-Allow-Origin: *. Personal accounts use a different picker base URL (onedrive.live.com/picker).
- **effort**: Medium: 1 to 2 days (MSAL plus picker messaging protocol).
- sources: https://learn.microsoft.com/en-us/graph/api/driveitem-get-content https://learn.microsoft.com/en-us/onedrive/developer/controls/file-pickers/ https://changelog.keboola.com/onedrive-file-picker-upgraded-to-microsofts-latest-version/ curl CORS preflight test 2026-10-13: https://graph.microsoft.com/v1.0/me/drive/items/{id}/content
### Audius (open API)
- **whatWorks**: Full DJ engine on a large free catalogue: search, trending, playlists, and full-length streams fetched as MP3 and decoded into PCM. Track JSON already includes 'bpm' and 'musical_key' (seen in /v1/tracks/trending on 2026-10-13), so TwinSpin can pre-sort by tempo and key. Optional 'Log in with Audius' (OAuth PKCE) for the user's favourites and playlists. Gated (purchase or follow) tracks return 401 without a signature, so filter them out.
- **requirements**: No key needed for reads: GET https://api.audius.co/v1/tracks/trending?app_name=TwinSpin worked keyless on 2026-10-13. A free API key from api.audius.co/plans gives 10 req/s and 500k req/month; the key is 'Safe to include in client-side code'. The bearer token must never go in frontend code. OAuth PKCE: 'no backend server or client secret is required'.
- **termsAndLegal**: The REST guide says the API is 'entirely free to use' and asks you to 'always credit artists'. I found no separate API terms page and no clause about DJ or mixing; the audius.co terms page renders client-side and could not be read. The license field per track is mostly null. Practical rule: show artist name and link back to the track, and do not offer downloads unless is_downloadable is true. Lowest legal risk among streaming catalogues because artists upload to Audius for open streaming.
- **technical**: GET /v1/tracks/{id}/stream?app_name=... returns a 302 to the content node, then a 307 to a presigned R2 URL, ending in a 206 audio/mpeg response. Every hop sends Access-Control-Allow-Origin: * and Range works (tested 2026-10-13). The file observed was 8.4 MB for 210 s, about 320 kbps, so fetch() plus decodeAudioData works directly. No DRM, no EME. The stream URL is signed and time-stamped, so fetch it when loading the deck.
- **effort**: Low to medium: 1 to 2 days (search/browse UI, attribution UI, fetch to existing decoder; OAuth optional +1 day).
- sources: https://docs.audius.co/developers/guides/rest-api https://docs.audius.co/llms-full.txt https://cdn.jsdelivr.net/npm/@audius/sdk@15.3.1/README.md https://openaudio.substack.com/p/introducing-the-open-audio-protocol curl test 2026-10-13: https://api.audius.co/v1/tracks/trending and https://api.audius.co/v1/tracks/GEG9ZWx/stream
### Jamendo API v3
- **whatWorks**: Full DJ engine on a Creative Commons indie catalogue (about 600k tracks): search by tags or fuzzytags, 'speed' tempo buckets (verylow to veryhigh, no numeric BPM), and stream MP3 (mp31 is 96 kbps, mp32 is VBR good quality) or OGG, decoded into PCM. Download links are given only when audiodownload_allowed is true.
- **requirements**: Free developer account and client_id (read-only plan by default); the key goes in the query string and is public. Request limits are not published officially; third parties cite 35,000 requests/month for non-commercial use. Commercial use, including ads or affiliate income, needs a paid licence (contact Jamendo).
- **termsAndLegal**: API terms (last modified 2013-09-17): credit the artist and Jamendo, link each track to its Jamendo page, use the unmodified logos, and no apps 'designed specifically to cache' content or offer offline access. Each track carries its own CC licence. All include BY (attribution); NC means non-commercial only; ND (NoDerivatives) is arguably infringed by beat-matched, blended mixes that get recorded or distributed. Playing ND tracks live and privately is low risk, but a recorded mix should exclude ND tracks (filter ccnd=false).
- **technical**: Tested 2026-10-13: api.jamendo.com returns Access-Control-Allow-Origin: *. The audio hosts mp3l.jamendo.com (ACAO *) and prod-1.storage.jamendo.com (reflects the origin) return 206 audio/mpeg with Range support. No DRM. Use audioformat=mp32 for better quality.
- **effort**: Low to medium: about 1 day.
- sources: https://developer.jamendo.com/v3.0/tracks https://developer.jamendo.com/v3.0/authentication https://devportal.jamendo.com/api_terms_of_use https://support-artist.jamendo.com/creative-commons-explained https://github.com/creativecommons/cccatalog/issues/345 curl CORS test 2026-10-13: api.jamendo.com/v3.0/tracks, mp3l.jamendo.com, prod-1.storage.jamendo.com
### Internet Archive (archive.org)
- **whatWorks**: Full DJ engine on public-domain, CC and taper-friendly material: Live Music Archive (etree), netlabels, old 78s. Use advancedsearch to find items, /metadata/{id} to list files, then fetch the MP3/OGG/FLAC from /download/ and decode.
- **requirements**: No key, no account, no backend.
- **termsAndLegal**: Rights vary per item. A default non-commercial terms statement applies unless the uploader says otherwise; the older (2011) terms say access is for 'scholarship and research purposes only'. Prefer collections with explicit CC or public-domain marks, or etree bands that allow trading. The Great 78 Project lawsuit settled confidentially in September 2025; avoid relying on 78s.
- **technical**: Tested 2026-10-13: advancedsearch.php and /metadata return Access-Control-Allow-Origin: * and allow Range. /download/... returns a 302 to a dn*.archive.org node, which returns 206 audio/mpeg, both with ACAO *. No DRM. Expect slow servers at times.
- **effort**: Low to medium: about 1 day (search UI over metadata).
- sources: https://archive.org/advancedsearch.php https://help.archive.org/help/internet-archive-access-policy/ https://publicdomainreview.org/collections/source/internet-archive/28 https://www.musicbusinessworldwide.com/labels-settle-copyright-lawsuit-against-internet-archive-over-streaming-of-vintage-vinyl-records curl CORS test 2026-10-13: archive.org/metadata/gd1977-05-08.shure57.stevenson.29303.flac16 and /download/... mp3
### Bandcamp (purchases)
- **whatWorks**: No API integration possible. But the user's purchases download DRM-free (MP3 V0, MP3 320, FLAC, AAC, Ogg, ALAC, WAV, AIFF) and already load through TwinSpin's local file input with the full DJ engine. Combined with a cloud picker, a user can drop Bandcamp downloads into Dropbox or Drive and load them on a phone. The Bandcamp embed player is an iframe only, with no Web Audio access.
- **requirements**: The user buys and downloads the music; no developer setup.
- **termsAndLegal**: Personal use of purchased files. There is no official consumer or fan API; community tools use undocumented endpoints and session cookies, so do not integrate them.
- **technical**: Nothing to build beyond a help tip; WAV/AIFF/FLAC decode in modern browsers (FLAC and ALAC support varies; prefer MP3 320 or WAV on iOS).
- **effort**: Trivial: documentation or help text only.
- sources: https://get.bandcamp.help/en/articles/15263234-in-which-formats-can-i-download-my-purchases https://github.com/iliana/bandcamp-dl https://www.val.town/x/tmcw/bandcampWrapped
### YouTube (IFrame Player API)
- **whatWorks**: Play-only. The music-player page could embed visible YouTube players (two iframes allow a crude volume-ramp 'crossfade'), with play/pause/seekTo, setVolume, and setPlaybackRate (a suggestion only). No Web Audio: no BPM analysis, EQ/FX, scratching, beat sync, or waveform.
- **requirements**: No key needed to embed by video ID. Searching needs a YouTube Data API key (exposed client-side, restrict by HTTP referrer); as of the quota doc updated 2026-10-08, search.list has its own 100 calls/day bucket and other calls draw from 10,000 units/day.
- **termsAndLegal**: Developer Policies (updated 2026-09-14): must not 'separate, isolate, or modify the audio or video components'; must not 'download, import, backup, cache, or store'; no offline playback; no background player; must not modify the player beyond the documented API. Required Minimum Functionality: player at least 200x200 px, no overlays on the player.
- **technical**: Cross-origin iframe; audio is not reachable from Web Audio, and extracting it violates the terms. Mobile browsers block unmuted autoplay without a user gesture; the player must stay visible, so no lock-screen play.
- **effort**: Medium: 1 to 2 days for a separate play-only 'YouTube mode' in the player page; not usable in the DJ decks.
- sources: https://developers.google.com/youtube/terms/developer-policies https://developers.google.com/youtube/terms/required-minimum-functionality https://developers.google.com/youtube/iframe_api_reference https://developers.google.com/youtube/v3/determine_quota_cost
### SoundCloud API
- **whatWorks**: Technically, full-length playback of 'playable' public tracks via AAC HLS (hls.js or MSE), and in theory segment fetch plus decode. In practice not usable for TwinSpin's DJ engine because of the terms and the secret requirement. Alternative: the SoundCloud iframe Widget for play-only, with no Web Audio.
- **requirements**: App registration needs an Artist Pro subscription: self-serve Client ID and Secret since May 2026 (blog post 2026-05-18); before that, registration was closed or waitlisted. 'All clients are currently treated as confidential', so a secret is required even for the client-credentials flow, and that needs a server or proxy (not possible on a pure static site without exposing the secret). Client-credentials limits: 50 tokens per 12 h per app.
- **termsAndLegal**: API Terms (effective 2024-03-30): no 'adaptation, editing, excerpting, or creating derivative works' unless the uploader expressly consents; no app that 'aggregates and streams User Content with content from other services'; no file-save; session caching only; attribution and backlinks required. The help centre says public APIs generally 'cannot be used for commercial use cases'. DJ mixing and blending with local or other-source tracks conflicts with these terms.
- **technical**: Progressive MP3, HLS MP3 and HLS Opus were scheduled for removal on 2025-12-31 (post dated 2025-09-15); hls_aac_160_url is preferred and hls_aac_96_url is a fallback; preview_mp3_128_url remains. The API supports CORS per its guide; CDN CORS was not verified. Tracks have access: playable, preview or blocked.
- **effort**: High, needs a proxy server, and is terms-blocked for DJ use. Not recommended.
- sources: https://developers.soundcloud.com/blog/api-streaming-urls https://developers.soundcloud.com/blog/page-data/vibe-coding-ai-agent-docs-self-serve-api-keys/page-data.json https://developers.soundcloud.com/docs/api/register-app https://developers.soundcloud.com/docs/api/guide https://developers.soundcloud.com/docs/api/terms-of-use https://help.soundcloud.com/hc/en-us/articles/115003446727
### Apple Music (MusicKit JS)
- **whatWorks**: Play-only: full tracks for Apple Music subscribers through MusicKit's own player (queue, shuffle, repeat). No Web Audio: audio is DRM-protected (EME), so no BPM analysis, EQ, scratch, or two-deck mixing. Even on iOS, MusicKit crossfade is internal and two independent decks are not possible (forum question of August 2026 had no answer).
- **requirements**: Apple Developer Program membership (paid yearly) to create a MusicKit key and sign a developer JWT (max about 180 days; can be pre-generated and embedded on a static site, but it is then public). Users need an Apple Music subscription. Chromium plays full tracks only over https or localhost; forum reports mention previews only otherwise.
- **termsAndLegal**: DPLA 3.3.6(D) as quoted on Apple's forums: 'MusicKit Content cannot be synchronized with any other content'. App Review 4.5.2 says MusicKit does not replace licences for deeper integrations. DJ use is partner-only: 'DJ with Apple Music' launched 2025-03-25 with rekordbox, Serato, Engine DJ/Denon/Numark/RANE, and djay.
- **technical**: MusicKit JS v3 with FairPlay or Widevine EME; a CDM can refuse to output audio anywhere but the hardware, and browsers block Web Audio readback of EME media.
- **effort**: Medium for a play-only mode (1 to 2 days plus the developer fee); impossible for the DJ engine.
- sources: https://developer.apple.com/forums/thread/843627 https://developer.apple.com/forums/thread/838157 https://developer.apple.com/forums/thread/683958 https://developer.apple.com/forums/thread/786423 https://djmag.com/tech/you-can-now-dj-apple-music-using-rekordbox-serato-and-more https://musicbusinessworldwide.com/apple-music-integrates-with-dj-apps-to-let-subscribers-mix-their-entire-music-library https://lists.w3.org/Archives/Public/public-audio/2014JanMar/0032.html https://bugzilla.mozilla.org/show_bug.cgi?id=1071482
### TIDAL
- **whatWorks**: Nothing useful for DJ. The public Web SDK (January 2024) plays preview tracks only; full-length third-party playback was 'aiming' for later in 2024, with no confirmed release found. Playback bytes are only through TIDAL's Player SDK (DRM).
- **requirements**: TIDAL developer account (OAuth 2.0, PKCE for user context). The DJ Extension is a paid add-on usable only inside partner apps.
- **termsAndLegal**: DJ Extension partners: rekordbox, Serato, djay Pro, edjing, Denon DJ, DJUCED, DEX 3, Tribe XR. There is no public application path for DJ partner access.
- **technical**: DRM via the official player; no Web Audio access.
- **effort**: Not feasible.
- sources: https://github.com/orgs/tidal-music/discussions/40 https://github.com/orgs/tidal-music/discussions/70 https://listen.tidal.com/djs https://support.tidal.com/hc/en-us/articles/23052303648529-Tidal-for-Developers https://serato.com/dj/pro/downloads/3.1.3
### Beatport Streaming (formerly LINK; Beatsource merged in 2026)
- **whatWorks**: Nothing for TwinSpin. Streaming works only in partner DJ software and hardware (rekordbox, Serato, Traktor, Engine DJ, djay, VirtualDJ; Cross DJ added June 2026) and in Beatport's own browser DJ app.
- **requirements**: The v4 API (api.beatport.com/v4/docs) uses OAuth authorization code and is gated to approved partners via a Partner Portal, decided case by case (third-party profile, unverified officially). The user needs a Beatport Streaming tier that includes DJ integration.
- **termsAndLegal**: Partner contracts only. Beatsource merged into Beatport starting 2026-03-03.
- **technical**: Partner-only streaming tech; not available to independent web apps.
- **effort**: Not feasible without a business partnership.
- sources: https://providers.apievangelist.com/providers/beatport/ https://github.com/orgs/music-assistant/discussions/4039 https://www.beatportal.com/articles/1291036-beatport-and-beatsource-to-unite-into-one-premium-dj-platform https://www.beatportal.com/articles/1489112-cross-dj-adds-beatport-streaming-compatibility https://www.digitaldjtips.com/its-official-beatsource-is-merging-into-beatport/
### Deezer API
- **whatWorks**: Only 30-second previews: search via the public unauthenticated API, then fetch the preview MP3 (about 480 KB) into Web Audio. Usable as a 'preview or discovery' feature, not for real sets. Full tracks only through Deezer's own plugins or SDK for Premium users; not available to third-party web apps via the API.
- **requirements**: New developer app creation is closed (portal message reported; GitHub issue says still disabled as of September 2026), so no OAuth or user library. Public search and preview calls need no app.
- **termsAndLegal**: Guidelines: API gives 'no audio streaming available except 30s extracts'; full-track URLs 'must never be accessible to the end-user'; 'Local Storage/Offline Storage of audio data is strictly forbidden'. Mixing is not addressed.
- **technical**: Tested 2026-10-13: the api.deezer.com JSON response has no Access-Control-Allow-Origin header (CORS fails), but output=jsonp works. Preview MP3s on cdnt-preview.dzcdn.net return Access-Control-Allow-Origin: * and allow Range. URLs are signed and expire after about 15 to 20 minutes, so fetch them right away.
- **effort**: Low (about half a day), but of little value for a DJ app.
- sources: https://developers.deezer.com/guidelines https://github.com/FoxxMD/multi-scrobbler/issues/175 https://github.com/holgerkrupp/Macamp/issues/18 https://pypi.org/project/deezer-oauth-cli/ https://dev.to/reynaldi/create-a-cool-music-chart-site-with-deezer-api-no-backend-needed-386e curl CORS test 2026-10-13: api.deezer.com/search and cdnt-preview.dzcdn.net preview MP3
## Findings
- [high,critical] Audius full-length streams are CORS-open MP3 that decodeAudioData can use directly. /v1/tracks/{id}/stream?app_name=X goes through 302 and 307 redirects to a 206 audio/mpeg response (about 320 kbps), with Access-Control-Allow-Origin: * on every hop, Range supported, and no API key required (tested 2026-10-13).
- [high] Audius track metadata already includes bpm and musical_key fields, and gated tracks return 401 without a signature. The free key tier is 10 req/s and 500k/month; the key is safe client-side; OAuth PKCE login needs no backend or secret.
- [medium] No Audius API terms page or DJ/mixing clause was found. The only stated condition is to credit artists (the API is 'entirely free to use').
- [high] Jamendo's API and its MP3 storage hosts send CORS headers (ACAO * or reflected origin, 206 with Range). It needs a free client_id; commercial use needs a paid licence; per-track CC licences apply, and ND tracks are risky in recorded or distributed beat-matched mixes.
- [high] Internet Archive search, metadata and download endpoints (including the redirect to dn*.archive.org) all return Access-Control-Allow-Origin: * and support Range, with no key needed. Rights are per item; the Great 78 suit settled confidentially in September 2025.
- [high,critical] All three cloud-drive routes work from a static site with no backend. Dropbox Chooser direct links support CORS (4-hour expiry, no production approval). Google Drive alt=media with a GIS token and the non-sensitive drive.file scope passes the CORS preflight from ranama.github.io. OneDrive must use the preauthenticated @microsoft.graph.downloadUrl, not /content, whose 302 breaks the CORS preflight.
- [high,critical] YouTube Developer Policies (updated 2026-09-14) forbid separating, isolating or modifying the audio, downloading or caching, and background players. The IFrame API exposes no raw audio, so YouTube can only be a visible play-only player (minimum 200x200, no overlays).
- [high,critical] SoundCloud: app registration reopened in May 2026 but only for Artist Pro subscribers. Every token flow requires the client secret, so a server is needed. Progressive MP3, HLS MP3 and HLS Opus were scheduled for removal on 2025-12-31, leaving AAC HLS. The API Terms forbid editing or adapting User Content without uploader consent and aggregating it with other services' content, which blocks DJ mixing.
- [high] Apple Music DJ mixing is partner-only ('DJ with Apple Music', launched 2025-03-25: rekordbox, Serato, Engine DJ, djay). MusicKit JS audio is DRM/EME-protected and cannot be routed through Web Audio, and the developer agreement bars synchronizing MusicKit content with other content.
- [medium] TIDAL's public Web SDK offers preview playback only (full-length promised for 2024, not confirmed), and its DJ Extension works only in partner apps. Beatport Streaming is partner-only via a gated v4 API, and Beatsource merged into Beatport from March 2026.
- [high] Deezer has disabled new developer app creation (still reported in September 2026), and its API gives only 30-second previews. The api.deezer.com JSON has no ACAO header (use JSONP), while preview MP3s are CORS-open but signed with a short expiry. Its guidelines forbid offline storage of audio.
- [high] Bandcamp has no consumer API. Purchases download DRM-free in MP3 V0/320, FLAC, AAC, Ogg, ALAC, WAV and AIFF, so they already work through TwinSpin's local file loader or a cloud picker.
