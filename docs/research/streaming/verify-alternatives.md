# verify-alternatives
- **confirmed**: 1. Audius full-length streams are CORS-open MP3 that decodeAudioData can use directly. /v1/tracks/{id}/stream?app_name=X goes 302 then 307 to a 206 audio/mpeg response (~320 kbps), with ACAO * on every hop, Range supported, and no API key required.
  - CORRECTION: Re-tested on 2026-10-13 with Origin https://ranama.github.io on track GEG9ZWx. Hops: (1) api.audius.co 302 with ACAO *; (2) creatornode.audius.co 307 with ACAO *; (3) a Cloudflare R2 presigned URL returning 206 audio/mpeg with ACAO *, Accept-Ranges and Content-Range bytes 0-1023/8405906. That is 8,405,906 B over 210 s, about 320 kbps. The bytes start with an ID3 MP3 header. The OPTIONS preflight with a Range header returns 204 with ACAO * and allow-headers: range. Only app_name was sent, no key. Missing caveat: the final R2 URL carries X-Amz-Expires=300, so it is valid for only 5 minutes. Resolve the /stream URL right before fetch() and never store the resolved URL. The redirect works from a browser only because every hop sends ACAO *: after a cross-origin redirect the Origin becomes 'null', and no credentials are sent.
- **partly-true**: 2. Audius track metadata includes bpm and musical_key; gated tracks return 401 without a signature; the free key tier is 10 req/s and 500k/month; the key is safe client-side; OAuth PKCE login needs no backend or secret.
  - CORRECTION: bpm and musical_key are present (sample: bpm 123, musical_key 'E flat minor', plus the flags is_custom_bpm and is_custom_musical_key). The SDK README confirms the plan figures ('10 requests/second', '500,000 requests/month', Free plan 'always free'). It also says the API Key is 'Safe to include in client-side code' while the Bearer Token is backend-only. The docs confirm PKCE: 'no backend server or client secret is required'. However, the redirect_uri must be registered in the developer app settings, and write scope needs an API key (app_name is enough for read scope). Wrong part: tracks gated with stream_conditions (USDC purchase, follow-gated) returned 403 {"error":"track not streamable"}, not 401, and preview=true also returned 403. The docs mention 401 only for 'programmable distribution' tracks gated with access_authorities. Filter tracks with is_stream_gated, stream_conditions or access.stream before trying to play them.
- **refuted**: 3. No Audius API terms page or DJ/mixing clause was found; the only stated condition is to credit artists (the API is 'entirely free to use').
  - CORRECTION: Audius does have API Terms: 'API Terms', Last Updated 2 July 2025. They are linked from audius.co/legal/api-terms and served as the PDF https://audius.co/documents/ApiTerms.pdf. They contain no explicit DJ, mixing or sync clause, so mixing is neither expressly banned nor expressly licensed. They do impose real conditions. (a) Only 'session-based caching' is allowed, and cached content must become inaccessible when the session ends, so no persistent IndexedDB or Cache API storage of decoded Audius audio and no offline library. (b) You must give your App Users the Audius Privacy Policy and these API Terms, so link both in TwinSpin. (c) No scraping or data harvesting, no benchmarking, and no bypassing or disabling features. That means respecting gating, and the Audius docs do not cover recording or exporting a mix that contains Audius audio. (d) No AI or ML training on content. (e) No facilitating 'unauthorized use of copyrighted content'. (f) Uploaded content falls under the Open Music License. Audius may terminate access at any time without notice. I found no artist-credit requirement in the developer docs. The docs describe the API as 'free, open', and the SDK README says the Free plan is 'always free'. The exact phrase 'entirely free to use' was not found.
- **partly-true**: 4. Jamendo's API and its MP3 storage hosts send CORS headers (ACAO * or reflected origin, 206 with Range). It needs a free client_id; commercial use needs a paid licence; per-track CC licences apply; ND tracks are risky in recorded or distributed beat-matched mixes.
  - CORRECTION: api.jamendo.com sends ACAO * (tested). The storage CORS claim is unreliable. prod-1.storage.jamendo.com, the host the API returns in the 'audio' and 'audiodownload' fields, sends 'Vary: Origin' but appears to cache the reflected ACAO of whoever fetched the file first. In tests from Origin https://ranama.github.io, 4 of 12 track/format combinations failed. Three had no ACAO at all (1848357 mp32, 1886257 mp31, 1214935 mp31). One returned 'Access-Control-Allow-Origin: http://localhost:3000' to every origin (1532771 mp31). The browser blocks all four. The legacy hosts mp3l.jamendo.com (mp31) and mp3d.jamendo.com (mp32) returned ACAO * for all 6 tracks, but they are undocumented. TwinSpin would need a fallback (rewrite to mp3l/mp3d, or retry). Other points: the default 'audio' format mp31 is only 96 kbps, so request audioformat=mp32 (VBR) for DJ use. The demo client_id in the docs (709fa152) now returns 'Your application has been suspended', so you need your own free client_id. The API Terms (last modified 17 Sept 2013) say 'may be used freely for non-commercial uses'. For commercial use you contact licensing@jamendo.com; no published paid plan was found. You must credit the artists and 'provide a direct backlink' to each track page. Apps must not be 'designed to cache the content' or offer offline access. The ND risk assessment is reasonable, since CC licences govern adaptations.
- **confirmed**: 5. Internet Archive search, metadata and download endpoints (including the redirect to dn*.archive.org) all return ACAO * and support Range, with no key. Rights are per item; the Great 78 suit settled confidentially in September 2025.
  - CORRECTION: Tested on 2026-10-13. advancedsearch.php, services/search/v1/scrape and /metadata/{id} return ACAO *. /download/{id}/{file} returns 302 with ACAO * to dn720301.ca.archive.org, which returns 206 audio/mpeg with ACAO * and a Content-Range. The preflight returns 204 and allows Range. No key is needed. On the first attempt the dn node returned a transient HTTP 500 with no ACAO header. A browser reports that as an opaque CORS or network error, so add a retry. The Great 78 settlement checks out: a joint notice was filed on 15 Sept 2025 and the terms are confidential. Missed ToS point: the archive.org Terms of Use (dated 31 Dec 2014) say access 'is granted for scholarship and research purposes only'. For a DJ or entertainment app, rely on each item's own licence (licenseurl, such as CC netlabels) or public-domain status, not on general IA access.
- **confirmed**: 6. All three cloud-drive routes work from a static site with no backend: Dropbox Chooser direct links support CORS (4-hour expiry, no production approval); Google Drive alt=media with a GIS token and drive.file passes the CORS preflight from ranama.github.io; OneDrive must use @microsoft.graph.downloadUrl, not /content, whose 302 breaks the CORS preflight.
  - CORRECTION: Each part checks out. Dropbox: the docs say direct links 'support CORS', 'expire after four hours', and that the Chooser 'doesn't require production approval'. You must register your domains. dl.dropboxusercontent.com answered with ACAO * and allows Range. Google: the OPTIONS preflight to www.googleapis.com/drive/v3/files/x?alt=media from ranama.github.io returned ACAO https://ranama.github.io with allow-headers authorization. drive.file is listed as non-sensitive and recommended, but it still needs 'basic OAuth App Verification' (brand verification) to run in production for outside users. GIS tokens last about an hour and have no refresh token. OneDrive: Microsoft's docs state the /content 302 limitation exactly as claimed, and say downloadUrl 'might expire within minutes'. Missed requirements: since personal-account app registrations outside a directory were deprecated, a OneDrive app now needs an Entra tenant, for example a free Azure account. Dropbox also says direct links 'should not be used to display content directly in the browser'. Fetching and decoding them is fine.
- **confirmed**: 7. YouTube Developer Policies (updated 2026-09-14) forbid separating, isolating or modifying the audio, downloading or caching, and background players; the IFrame API exposes no raw audio, so YouTube can only be a visible play-only player (minimum 200x200, no overlays).
  - CORRECTION: Each item matches the current policy text, listed under 'evidence'. Add one rule that matters for a two-deck UI: the Required Minimum Functionality rules (updated 2026-09-14) say a page 'must not have more than one YouTube player that automatically plays content simultaneously'. Playback also must not start automatically until the player is visible. III.I.6 bars modifying or building on the player. Do not route the player through Web Audio and do not attempt crossfades between two YouTube players.
- **confirmed**: 8. SoundCloud: app registration reopened in May 2026 but only for Artist Pro subscribers; every token flow requires the client secret, so a server is needed; progressive MP3, HLS MP3 and HLS Opus scheduled for removal on 2025-12-31, leaving AAC HLS; API Terms forbid editing/adapting User Content without uploader consent and aggregating it with other services' content.
  - CORRECTION: Confirmed by primary sources. The registration page says 'You need a SoundCloud Artist Pro subscription to register API applications'. The SoundCloud blog post of 18 May 2026 announced self-service credentials. The API guide says 'All clients are currently treated as confidential... a secret is required to obtain a token'. Client-credentials tokens are also limited to 50 per 12 hours per app and 30 per hour per IP. The blog's 'Deadline Extended' post names 31 Dec 2025 for removing http_mp3_128_url, hls_mp3_128_url and hls_opus_64_url, leaving hls_aac_160_url and hls_aac_96_url; preview_mp3_128_url remains. API Terms (effective 30 March 2024), section 03, ban modification 'including adaptation, editing, excerpting' without the uploader's express consent and 'any playback experience which aggregates and streams User Content with content from other services'. Section 05 allows session-only caching.
- **confirmed**: 9. Apple Music DJ mixing is partner-only ('DJ with Apple Music', launched 2025-03-25: rekordbox, Serato, Engine DJ, djay); MusicKit JS audio is DRM/EME-protected and cannot be routed through Web Audio; the developer agreement bars synchronizing MusicKit content with other content.
  - CORRECTION: The launch was reported on 25 March 2025 for rekordbox, Serato and Engine DJ, with djay as an existing partner. The current Apple Developer Program License Agreement says developers may not 'download, upload, or modify any MusicKit Content', that 'MusicKit Content cannot be synchronized with any other content', and that content may be played 'only as rendered by the MusicKit APIs or MusicKit JS'. That language forbids routing it through a Web Audio DJ engine regardless of DRM. I did not re-check the EME/DRM mechanism against a primary source in this pass, but the licence text alone is decisive. MusicKit also requires a paid Apple Developer Program membership to sign developer tokens.
- **partly-true**: 10. TIDAL's public Web SDK offers preview playback only (full-length promised for 2024, not confirmed); its DJ Extension works only in partner apps; Beatport Streaming is partner-only via a gated v4 API; Beatsource merged into Beatport from March 2026.
  - CORRECTION: The TIDAL part holds up. The Web SDK announcement (23 Jan 2024) covers 'playback of TIDAL preview tracks'. On 28 Aug 2024 a maintainer said 'We currently don't have a fixed date for full-length playback' and aimed for 'later this year'. No later update appears. The DJ Extension being partner-only was not re-verified against a primary source here. The Beatport v4 partner gating is supported only by third-party sources, such as API directories and beets plugin authors saying normal credential access is unavailable; I found no official Beatport page. On Beatsource, the merger was announced in March 2026, but migration is opt-in and was rolled out over the following weeks or months. It is not a completed merger 'from March 2026'.
- **partly-true**: 11. Deezer has disabled new developer app creation (still reported in September 2026); its API gives only 30-second previews; api.deezer.com JSON has no ACAO header (use JSONP); preview MP3s are CORS-open but signed with a short expiry; guidelines forbid offline storage of audio.
  - CORRECTION: The technical points were confirmed on 2026-10-13. api.deezer.com/search returns Access-Control-Allow-Methods and Allow-Headers but no Access-Control-Allow-Origin, so fetch() fails while JSONP (output=jsonp&callback=) works. Preview URLs on cdnt-preview.dzcdn.net return 206 with ACAO * and carry an hdnea exp token about 15 minutes ahead. The guidelines say 'Local Storage/Offline Storage of audio data is strictly forbidden' and allow only '30s extracts'. The closure is real: the portal shows 'We're not accepting new application creation at this time'. However, the latest dated report I found is a Deezer Community thread from 8-9 June 2026 (reply from a 'Superuser', not identified as staff); the 'September 2026' date is unverified. Public read endpoints such as search and track need no app at all, so 30-second previews do not depend on the closure.
- **partly-true**: 12. Bandcamp has no consumer API; purchases download DRM-free in MP3 V0/320, FLAC, AAC, Ogg, ALAC, WAV and AIFF, so they already work through TwinSpin's local file loader or a cloud picker.
  - CORRECTION: Bandcamp's only APIs (Account, Sales Report, Merch Orders) are for labels and fulfilment partners, and the eight formats are confirmed. However, 'already work' depends on the format. decodeAudioData support for ALAC (.m4a) and AIFF is not cross-browser: it is mainly Safari, and a primary per-browser table was not confirmed here. Ogg Vorbis has historically been weak on Safari. Tell users to download MP3 320, FLAC or WAV, and catch decode errors with a message about the format.
## Extra findings
- Audius API Terms (2 July 2025, https://audius.co/documents/ApiTerms.pdf): only session-based caching is allowed, so TwinSpin must not persist decoded Audius PCM or MP3 bytes across sessions. TwinSpin must show users the Audius API Terms and Privacy Policy. Exporting or recording a mix that contains Audius tracks is not covered by any grant.
- Audius stream URLs end in a Cloudflare R2 presigned URL with X-Amz-Expires=300 (5 minutes). Call /v1/tracks/{id}/stream at deck-load time, never cache the resolved URL, and filter on is_stream_gated, stream_conditions and access.stream. Gated tracks return 403, not 401.
- Jamendo CORS defect: prod-1.storage.jamendo.com, the host the API returns, caches the first requester's reflected Access-Control-Allow-Origin, for example 'http://localhost:3000', and sometimes sends none. 4 of 12 track/format combinations tested from ranama.github.io would be blocked. mp3l.jamendo.com/?trackid=ID&format=mp31 and mp3d.jamendo.com/?trackid=ID&format=mp32 returned ACAO * consistently but are undocumented. The default mp31 format is 96 kbps; use mp32.
- Internet Archive Terms of Use (31 Dec 2014) grant access 'for scholarship and research purposes only'. For DJ use, show and filter by each item's licenseurl (CC or public domain) instead of treating all of archive.org as fair game. Transient dn-node 500 responses have no ACAO, so add retries.
- Suno (the user asked about it): no public API exists. Suno announced an invite-only developer partner programme on 1 July 2026, with no timeline or pricing (https://www.digitalmusicnews.com/2026/07/03/suno-is-opening-an-api-partner-program/). Unofficial wrappers reverse-engineer the app and carry ToS risk. The practical path is to download your own Suno songs and load them through TwinSpin's local or cloud loader. Since 3 Sept 2026 downloads are capped: Free 7 for life, Pro 20 a month, Premier 60 a month, Studio unlimited. The caps apply to existing libraries too; this follows the Nov 2025 Warner settlement (https://mubert.com/blog/suno-download-caps, which cites help.suno.com/en/articles/13614785; MBW coverage returned 403).
- Spotify (the user asked about it): the Spotify Developer Policy (effective 15 May 2025, https://developer.spotify.com/policy) III.7 says 'Do not permit any device or system to segue, mix, re-mix, or overlap any Spotify Content'. IV.1 limits streaming to Premium subscribers. Spotify DJ mixing is therefore barred by the terms, whatever the technical route.
- YouTube Required Minimum Functionality (2026-09-14) bars more than one autoplaying YouTube player at once. Any 'YouTube mode' must be a single visible player, not two decks.
- OneDrive route: new app registrations need an Entra tenant, because personal-account registrations outside a directory are deprecated. This is a free Azure account step, not a backend. Google drive.file needs basic (brand) OAuth app verification before production use with outside users.
- SoundCloud's embeddable Widget (iframe) player is a possible play-only option like YouTube that does not need a client secret. It was not verified in this pass, and the API Terms' rule against aggregating SoundCloud content with other services would still apply to mixing.
- Range with a single byte range is CORS-safelisted in current browsers, and all recommended hosts (Audius R2, IA dn nodes, Dropbox, OneDrive downloadUrl) either answer the preflight or return ACAO *. A plain fetch(url) followed by arrayBuffer() and decodeAudioData is enough; no Range requests are needed for whole-file decoding.
