# verify-suno
- **confirmed**: 1. No official public or self-serve Suno API as of 2026-10-13. On 2026-07-01 Suno's CPO said it is exploring a developer API with a curated partner group through an intake form. No docs, pricing or launch date, and the focus is generative experiences, not library playback.
  - CORRECTION: Accurate. Jack Brody (CPO) posted on LinkedIn on Wednesday 2026-07-01 and Digital Music News covered it on 2026-07-03. The form says Suno is 'beginning to explore a developer API, starting with a curated group of partners'. I found no API launch through 2026-10-13: September brought the v6 models (2026-09-09) and Believe/TuneCore deals, and October 1 brought the Speech beta, none of them an API. suno.com/api/docs returns 404 and the Terms never mention an API. Many 'Suno API' sites (sunoapi.org, musicapi.ai, aimusicapi.ai, sunor.cc, evolink) are unofficial resellers. Make.com's 'Suno' app actually uses sunoapi.org keys.
- **confirmed**: 2. Public song f0f00357-... (v6, created 2026-09-09, 240.4 s): audio_url is studio-api.prod.suno.com/api/forbidden; cdn1/cdn2.suno.ai/<id>.mp3 return 403; the old cdn1 mp3 trick no longer works, at least for current songs.
  - CORRECTION: Reproduced on 2026-10-13. The song page and the clip JSON show audio_url = https://studio-api.prod.suno.com/api/forbidden, major_model_version v6, model chirp-goose, created_at 2026-09-09T13:40:02Z and duration 240.4. The qualifier 'at least for current songs' is too cautious. A 2024 v3.5 public song (000123c5-3e53-40ee-8313-758c8e5961b5, created 2024-11-04) and three other IDs that the Wayback Machine captured as HTTP 200 in Dec 2024 now also return 403 on cdn1 and cdn2 .mp3. The old song also has audio_url /api/forbidden. The cdn1 403 body is a CloudFront 'MissingKey: Missing Key-Pair-Id query parameter or cookie value' error, so the MP3 path now needs CloudFront signed URLs or cookies; the files are not simply gone. GitHub issue gcui-art/suno-api #289 (opened 2026-08-29) reports the same three broken paths for a Pro account, so the change dates to late August 2026 or earlier.
- **confirmed**: 3. The player streams 'm4a-opus' (encoding 1.0.0) from d2lwuy8qc234o3.cloudfront.net/1/clip/<id>.m4a with ACAO * and range support, but the payload has no MP4 boxes and full entropy, so it looks obfuscated or encrypted. decodeAudioData can't use it, and undoing it would be circumvention.
  - CORRECTION: Reproduced. media_urls = [{content_type 'm4a-opus', delivery 'progressive', encoding '1.0.0'}]. The file is 3,958,805 bytes (about 132 kbps over 240 s) with Content-Type application/octet-stream. Byte entropy of the first 64 KB is 7.9976 bits/byte, all 256 byte values appear, and neither the head nor the tail contains ftyp, moov, mdat, OggS or OpusHead. GitHub issue #289 reports the same: ffprobe gives 'moov atom not found'. Nuances: (a) ACAO * is only returned when an Origin header is sent, and the CORS preflight (OPTIONS) returns 403, so only simple GETs work cross-origin and any preflighted request fails. (b) The embed player's scripts contain no EME calls (no requestMediaKeySystemAccess or Widevine; the only 'MediaKeys' hit is a react-query key name), but they do reference Web Crypto AES-CTR/GCM. That points to app-level encryption decrypted in JS rather than browser DRM. This is an inference, and I did not reverse-engineer it. (c) The circumvention point is backed by the Terms' ban on circumventing 'content protections' and on reverse engineering, not only by general law.
- **confirmed**: 4. The share video cdn1.suno.ai/<id>.mp4 is a plain MP4 (H.264 + AAC, ~7.9 MB) with ACAO * and CORP cross-origin; technically decodable, but extracting audio from it skips the download allowance and conflicts with the Terms.
  - CORRECTION: Headers and container confirmed: 206 video/mp4, 7,919,903 bytes, CORP cross-origin, ACAO * (when Origin is sent), last-modified 2026-09-09. It starts with ftyp isom/avc1, and its moov contains avc1, mp4a/esds and both 'soun' and 'vide' tracks. Nuances: the page's og/twitter meta tags advertise no video or audio, so the URL is not a published sharing channel. Not every song has one: the 2024 ID 00004802-... returns 403 for .mp4. Video is also an official Download format that counts against the allowance. The Terms sentence that settles it is 'Obtaining a copy of an Output by any means other than a download channel made available by Suno is prohibited'. I could not test in a browser whether decodeAudioData accepts this exact file, because browser tools were barred.
- **partly-true**: 5. CORS is not the limiting factor for Suno media: the audio stream, video and splash-clip hosts all send ACAO *. A proxy adds nothing legitimate. The blockers are the forbidden audio_url, the obfuscated stream, and the Terms.
  - CORRECTION: True for the media files: the m4a and mp4 hosts send ACAO *. I could not verify a 'splash-clip' host, because the clip JSON lists only audio_url, media_urls (m4a), video_url and images. CORS does block the metadata side for a static site. The clip metadata endpoint (studio-api.prod.suno.com/api/clip/<id>) and Suno's official oEmbed endpoint (studio-api-prod.suno.com/api/oembed) send no Access-Control-Allow-Origin for https://ranama.github.io, only 'vary: origin' and access-control-expose-headers. So a static TwinSpin cannot look up a song's title or art, or resolve a share link, from the browser. It can only build suno.com/embed/<id> from an ID parsed out of the URL. The m4a host's preflight also returns 403. The conclusion that a proxy would add nothing legitimate still holds.
- **confirmed**: 6. Suno Terms (last revised 2026-08-10, effective 2026-09-03) ban 'data mining, robots, scraping', say 'recording or stream ripping are prohibited', bar access 'through any means not intentionally made available', and allow commercial use of Output only if it is a permitted Download under the user's tier.
  - CORRECTION: All quotes match the live Terms: 'Date of Last Revision: August 10, 2026' and 'Effective Date: September 3, 2026'. The research left out several clauses that also matter. The Terms bar circumventing 'content protections' (directly relevant to the m4a-opus stream) and bar reverse engineering. Suno reserves the right to 'append a fingerprint, watermark, or metadata indicating the applicable service tier of an Output and whether such Output was a permitted Download'. Users must not remove those markings to conceal provenance or tier. And 'You may not commercially exploit Output that has not been downloaded by you through an approved channel'.
- **confirmed**: 7. Download caps since 2026-09-03 (announced 2026-08-10, after the Nov 2025 Warner settlement said downloads would need paid accounts): Free up to 7 lifetime trial downloads, non-commercial (accounts made after 09-03 may get fewer, more can be bought); Pro 20/month; Premier 60/month; Premier in Suno Studio unlimited; caps also apply to older songs; every song stays playable and shareable on every plan.
  - CORRECTION: All points match official sources. Details: monthly allowances reset on the billing date and do not roll over. Failed downloads do not count. Commercial rights in a Download are 'perpetual' and survive cancellation or downgrade. The Nov 25, 2025 WMG press release was stricter than the final policy: it said free-tier songs 'will not be downloadable'. The 2026-08-10 policy softened that to up to 7 trial downloads. Help article 13876865 words the Studio exception without a plan qualifier ('Workflows in Suno Studio will not be subject to download limits').
- **confirmed**: 8. Download formats: MP3 on all plans (web and mobile), WAV for Pro/Premier on suno.com, video, stems where they exist (no extra charge), MIDI for Studio songs on Premier; one song = one download regardless of format; re-downloads free.
  - CORRECTION: Matches help article 13926081 and the FAQ. Two caveats. (a) 'No extra charge' for stems means stems do not count as an extra download. Creating stems with Get Stems may still cost credits or need a paid plan; I could not verify this because the stem help article returned 404. (b) The live suno.com song page's UI strings include a download label 'M4A Audio' next to 'MP3 Audio' and 'WAV Audio'. An M4A option may exist or be on the way, but the help article does not list it, so treat it as unverified.
- **confirmed**: 9. Pro/Premier output is assigned to the user and paid-plan downloads 'remain yours to use commercially or personally'; Free/Basic output is personal and non-commercial only; trial downloads are not eligible for commercial use; Remixes are personal and non-commercial only; DJ use isn't addressed, so paid gigs or monetised streams need a paid-plan download.
  - CORRECTION: Quotes verified. Clarifications: (a) 'Remix' is a defined term in the Terms. It means a remix made through Suno's in-service feature that lets other users remix your Outputs, jointly owned and non-commercial 'regardless of your subscription tier'. It does not describe DJ mixing of your own downloaded file in an outside app. (b) The Terms say 'You may edit, process, or convert the format of an Output you are otherwise permitted to use to the extent such use is incidental'. That supports DJ processing (tempo, EQ, FX, re-encoding) of a permitted download, as long as nothing strips Suno's watermark or metadata to hide the tier. (c) Suno 'makes no representation or warranty ... that any copyright will vest in any Output'. (d) Free/Basic Output is not assigned to the user. (e) Any outside venue or platform (Twitch, YouTube, Mixcloud, a club) applies its own rules: 'subject to the terms, policies, and requirements of the third party'.
- **confirmed**: 10. gcui-art/suno-api is unofficial ('for learning and research purposes only'), needs the user's suno.com cookie plus paid 2Captcha hCaptcha solving via Playwright on a server; last commit 2026-03-06, not archived; it violates the Terms' bot/scraping bans and cannot run from a static site.
  - CORRECTION: GitHub API: archived=false, pushed_at 2026-03-06T17:24:20Z, latest commits 2026-03-06, 108 open issues. README requires SUNO_COOKIE and TWOCAPTCHA_KEY, uses Playwright with rebrowser-patches, and deploys via Vercel, Docker or Node. The research missed one thing: as of late August 2026 the tool reportedly cannot deliver playable audio at all. Issue #289 (2026-08-29) says audio_url is /api/forbidden, cdn1 mp3 returns 403, and the m4a-opus is encrypted, for a paid Pro user. It is therefore both against the Terms and broken for library playback.
- **confirmed**: 11. suno.com/embed/<id> returns 200 with no X-Frame-Options or frame-ancestors so it can be framed from ranama.github.io; suno.com/song/<id> cannot be framed (frame-ancestors 'none'); embed audio cannot reach TwinSpin's Web Audio graph.
  - CORRECTION: Headers reproduced. The embed page has no XFO and no CSP. The song page sends CSP frame-ancestors 'none' and also X-Frame-Options: SAMEORIGIN. The research missed that Suno publishes an official oEmbed discovery link on both song and embed pages (<link rel=alternate type=application/json+oembed href=https://studio-api-prod.suno.com/api/oembed?url=...>). That makes embedding a means Suno 'intentionally made available'. Its official snippet is <iframe width='100%' height='140' ... allow='autoplay; clipboard-write; encrypted-media; fullscreen; picture-in-picture' src='https://suno.com/embed/<id>'>. That oEmbed JSON has no CORS for third-party origins, so TwinSpin should build the iframe URL from the parsed ID itself. The iframe is cross-origin, so its audio cannot be captured by createMediaElementSource. I did not check whether embeds work for private or unlisted songs.
- **confirmed**: 12. No OAuth or PKCE sign-in exists for third-party apps; account access for other apps exists only via cookie copying in unofficial tools, so a static-site 'connect your Suno account' button isn't possible today.
  - CORRECTION: No OAuth, OIDC or PKCE program is documented. auth.suno.com/.well-known/openid-configuration returns 404, and gcui-art switched its auth endpoint from clerk.suno.com to auth.suno.com, meaning first-party Clerk auth. 'Only via cookie copying' is slightly too narrow. Unofficial access also comes through browser extensions that read the live Suno session and send it to a third party (for example the 'SunoFlow Connector', which sends the session to sunoflow.com) and through reseller 'Suno API' keys such as sunoapi.org via Make.com. All are unofficial, none give scoped library access, and all conflict with the Terms. The conclusion stands.
## Extra findings
- Terms clauses the research did not cite. The Terms bar circumventing 'content protections', which squarely covers decrypting the m4a-opus stream, and they bar reverse engineering. Suno also reserves the right to watermark or fingerprint Outputs with their service tier and whether they were a 'permitted Download', so copies obtained outside the Download channel can be traced. Source: https://suno.com/terms
- DJ processing of a downloaded file is supported by the Terms: 'You may edit, process, or convert the format of an Output you are otherwise permitted to use to the extent such use is incidental'. If TwinSpin ever records or exports mixes, it should not strip Suno's metadata or watermark for the purpose of concealing provenance or tier. Source: https://suno.com/terms
- Commercial rights in a Download are 'perpetual' and are not affected by later cancellation, downgrade or allowance changes. Suno also gives no warranty that copyright vests in any Output. Venue and platform rules (Twitch, YouTube, Mixcloud, clubs) still apply separately. Source: https://suno.com/terms
- The MP3 block is not limited to new songs. A 2024 v3.5 public song (000123c5-3e53-40ee-8313-758c8e5961b5) and three other IDs that the Wayback Machine captured as 200 in Dec 2024 now return 403 on cdn1/cdn2 .mp3 and show audio_url /api/forbidden. The cdn1 403 is 'MissingKey: Missing Key-Pair-Id', meaning CloudFront signed access is now required. GitHub issue #289 (2026-08-29) dates the change to late August 2026. Sources: https://web.archive.org/cdx/search/cdx?url=cdn1.suno.ai/* and https://github.com/gcui-art/suno-api/issues/289
- Static-site constraint for any 'paste a Suno link' feature, even the embed-only one. The official oEmbed endpoint (studio-api-prod.suno.com/api/oembed) and the clip metadata endpoint send no Access-Control-Allow-Origin for https://ranama.github.io. TwinSpin therefore cannot fetch a song's title or artwork, or resolve suno.com/s/<code> short share links, from the browser. It can only regex the UUID out of a suno.com/song/<uuid> or suno.com/embed/<uuid> URL and build the iframe. I did not test /s/ resolution because I had no sample code.
- Suno publishes an oEmbed discovery link on every song page, and the iframe snippet it returns is the official embed format: allow='autoplay; clipboard-write; encrypted-media; fullscreen; picture-in-picture', height 140. Using that exact snippet keeps the optional embed clearly within 'means intentionally made available'.
- Downloads are only offered for the user's own songs. I found no official channel to download another creator's public song (help.suno.com does not address it), so TwinSpin cannot legitimately DJ other people's Suno tracks unless the creator shares a file. Source: https://help.suno.com/en/articles/13876865 and the Terms download-channel sentence.
- Corrections to the PWA recommendation, per MDN browser-compat-data. Web Share Target (share_target) works in Chrome Android 76+, Chrome/Edge desktop 89+ and Opera, but not in Safari/iOS or Firefox, and it only works once the PWA is installed. File sharing needs method POST with enctype multipart/form-data. On GitHub Pages the service worker is mandatory, not optional, because the static host cannot accept the POST: the worker must intercept it and answer with a 303 redirect. For desktop, the File Handling API (manifest file_handlers plus launchQueue, Chrome/Edge 102+, not Android, Safari or Firefox) can add 'Open with TwinSpin' for .mp3/.wav. Source: https://raw.githubusercontent.com/mdn/browser-compat-data/main/manifests/webapp/share_target.json and file_handlers.json; https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/share_target
- Many third-party 'Suno API' services (sunoapi.org, musicapi.ai, aimusicapi.ai, sunor.cc, evolink.ai, and Make.com's 'Suno' app) are unofficial resellers focused on generation. They do not give access to a user's own Suno library, and their claims of official status are not backed by Suno.
- Suno's player and embed scripts make no browser-EME calls: no requestMediaKeySystemAccess or Widevine, and the one 'MediaKeys' hit is a react-query key name. They do reference Web Crypto AES-CTR/GCM. So the m4a-opus protection looks like app-level encryption rather than browser DRM. This is an inference from grepping 80 public JS chunks; I did not analyse it further.
